R&R FIGUEREDO TRANSPORTES — aplicação React e Supabase

Arquivos principais:
- react-app/index.html: entrada do sistema.
- react-app/src/: componentes, telas, regras de negócio e estilos React.
- react-app/redefinir-senha.html: recuperação de senha renderizada em React.
- banco-de-dados/supabase/app-config.js: URL, chave publicável e mapeamento dos usuários.
- banco-de-dados/supabase/supabase.sql: tabela compartilhada e políticas de acesso autenticado.
- banco-de-dados/supabase/supabase-visitor-role.sql: regras do perfil visitante.
- banco-de-dados/supabase/backup-supabase.ps1: ferramenta de backup lógico local.

Configuração:
1. No Supabase, confirme que os usuários necessários existem em Authentication > Users.
2. Confira o mapeamento USER_EMAILS em banco-de-dados/supabase/app-config.js e a correspondência com os e-mails autorizados pelas políticas RLS.
3. Em Authentication > URL Configuration, inclua a URL publicada terminada em /redefinir-senha.html nas Redirect URLs.
4. Execute npm install e npm run build na raiz para validar a compilação React.
5. Teste login, recuperação de senha, perfil visitante e permissões com contas de teste antes da publicação.

Publicação:
- A aplicação é compilada a partir de react-app/ usando Vite.
- O workflow .github/workflows/deploy-react.yml publica dist-react/ somente após confirmação manual.
- Não publique diretamente os arquivos-fonte nem configure GitHub Pages para servir a raiz do repositório como site estático.

Segurança:
- A chave publicável/anon é destinada ao navegador; nunca coloque service_role, senhas ou connection strings no código.
- A proteção dos dados depende das políticas RLS. Não execute SQL de permissões em produção sem revisar o projeto e fazer backup.
- Faça backups regulares e teste a restauração em um projeto separado.
- A refatoração de arquivos não altera tabelas nem dados do Supabase.
